# Үйл ажиллагаа үүсгэх API

`POST /events/create`

Headers:

```http
Content-Type: application/json
Authorization: Bearer <login эсвэл email баталгаажуулалтаас авсан token>
```

Хэрэглэгч идэвхтэй, email нь баталгаажсан, token нь хүчинтэй байх ёстой.

```json
{
  "baiguullagiindugaar": "org-1",
  "angilaliindugaar": "environment",
  "garchig": "Мод тарих өдөрлөг",
  "tailbar": "Хамтдаа мод тарина.",
  "bairshil": "Улаанбаатар",
  "ehleh_ognoo": "2030-10-20T10:00:00+08:00",
  "duusah_ognoo": "2030-10-20T12:00:00+08:00",
  "oroltsohchdiin_too": 10
}
```

- `argahemjeeniidugaar` өгөөгүй эсвэл `null` бол сервер UUID үүсгэнэ. Клиент тогтмол ID өгч давтан илгээвэл эхний хүсэлт хадгалагдаж, дараагийнх `409` болно.
- `tulwiindugaar` өгөөгүй бол `open`; `tailbar` өгөөгүй бол хоосон текст хадгална.
- Бусад талбар заавал байна. Текстүүдийн захын зайг арилгана. Model-ийн уртын хязгаарыг шалгана.
- Огноо нь цагийн бүстэй ISO 8601 утга байна. Дуусах огноо эхлэхээс хойш байна.
- Оролцогчдын тоо `1–2147483647` бүхэл тоо байна. Текст тоо, бутархай, boolean зөвшөөрөхгүй.
- Танигдахгүй талбаруудыг алдаа гэж буцаана.

Амжилттай хариу: `201 Created`.

```json
{
  "message": "Үйл ажиллагаа амжилттай үүсгэлээ.",
  "event": {
    "argahemjeeniidugaar": "серверийн-үүсгэсэн-uuid",
    "baiguullagiindugaar": "org-1",
    "angilaliindugaar": "environment",
    "tulwiindugaar": "open",
    "garchig": "Мод тарих өдөрлөг",
    "tailbar": "Хамтдаа мод тарина.",
    "bairshil": "Улаанбаатар",
    "ehleh_ognoo": "2030-10-20T10:00:00+08:00",
    "duusah_ognoo": "2030-10-20T12:00:00+08:00",
    "oroltsohchdiin_too": 10
  }
}
```

Validation алдаа: `400 Bad Request`.

```json
{
  "message": "Мэдээллээ шалгана уу.",
  "errors": {
    "duusah_ognoo": ["Дуусах огноо эхлэх огнооноос хойш байх ёстой."]
  }
}
```

Бусад төлөв: `401` нэвтрээгүй/баталгаажаагүй/хугацаа дууссан token, `405` буруу HTTP method, `409` давхардсан ID, `413` хүсэлт хэт том, `415` JSON content type дутуу.

Service: `events.services.create_event(...)` нь validation хийж, transaction дотор `Event` хадгалаад model instance буцаана. HTTP хариу, authentication, JSON serialization нь view-д тусдаа байна. Давхардсан ID-г database-ийн primary key constraint хамгаална; одоогийн бүртгэлийг солихгүй.

Байгууллага/ангилал/төлөв нь тусдаа FK хүснэгттэй. JSON талбарын нэр, текст ID формат хэвээр.
Ангилал, төлөв database-д урьдчилан бүртгэлтэй байна. Байгууллагын ID байхгүй бол
тэр текстийг нэр/дугаар болгон нэвтэрсэн хэрэглэгчийн эзэмшлийн байгууллага үүсгэнэ.
Байгаа байгууллагаар зөвхөн эзэмшигч нь нийтэлнэ; эзэмшигчгүй хуучин байгууллагыг администратор хуваарилна.
Бүтэц болон үүсгэх заавар: [DATABASE.md](../DATABASE.md).

## Жагсаалт, дэлгэрэнгүй, оролцогчийн бүртгэл

- `GET /events/?q=Мод&category=environment&limit=20&offset=0` — гарчиг/байршлаар хайж, ангиллаар шүүнэ. `limit` 1–100 байна. `upcoming=true` нь дуусах огноо болоогүй үйл ажиллагааг шүүнэ.
- Жагсаалтын хариу: `events`, нийт `count`, дараагийн хуудасны `next_offset` (байхгүй бол `null`).
- `GET /events/<id>/` — нэг үйл ажиллагаа; олдохгүй бол `404`.
- `POST /events/<id>/join` — хүчинтэй Bearer token-оор оролцогч болж бүртгүүлнэ.
- `POST /events/<id>/leave` — зөвхөн өөрийн бүртгэлийг цуцална.

Жагсаалт, дэлгэрэнгүйд нэвтрэлт шаардахгүй. Token өгвөл тухайн хэрэглэгчийн `is_joined` төлөвийг буцаана. Хариу бүрд `participant_count` байна; бусад оролцогчийн хувийн мэдээллийг буцаахгүй.

Оролцох/цуцлах үйлдлүүд `200` болон шинэчлэгдсэн `event` буцаана. Давтан оролцох нь шинэ мөр нэмэхгүй, давтан цуцлах нь алдаа өгөхгүй. Дууссан, `open` биш эсвэл багтаамж дүүрсэн үйл ажиллагаанд шинээр оролцохыг `409`-өөр татгалзана. Event мөрийг transaction дотор түгжиж шалгадаг тул PostgreSQL дээр зэрэг хүсэлт ирэхэд багтаамжийг хэтрүүлэхгүй. Database-ийн event/user unique constraint нь давхар бүртгэлээс хамгаална.

Flutter-ийн нүүр, жагсаалт, дэлгэрэнгүй, нийтлэх болон оролцох/цуцлах дэлгэцүүд эдгээр API-тай холбогдсон. Формд зохион байгуулагч, эхлэх/дуусах огноо/цаг, багтаамжийг авна. Алдаа гарвал мэдээллийг хадгалж үлдэнэ; дахин оролдоход нэг draft-ийн тогтмол ID-г ашиглаж давхар нийтлэхээс сэргийлнэ.
